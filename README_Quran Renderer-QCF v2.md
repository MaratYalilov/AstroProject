# Quran Renderer + QCF v2 - как всё устроено

Эта памятка нужна, чтобы через полгода вспомнить, откуда берутся аяты, как работает тег `{Quran}`, зачем нужны отдельные шрифты аятов V2 и страниц V4 и что пересобирать при изменениях. Здесь описано устройство системы, а не только последний переход на другой формат шрифтов.

Обновлено 11 октября 2026 года: сайт использует локальные WOFF2 вместо TTF; до загрузки нужного шрифта показывает читаемый арабский Unicode. Загрузчик сохраняет собственные объекты шрифтов, чтобы обновление CSS в режиме разработки не оставляло запасной текст навсегда. Данные `code_v2`, номера страниц и семейства QCF при этом сохранены.

Обновлено 18 октября 2026 года: шрифты страниц регистрирует только загрузчик. Статические определения тех же файлов в CSS удалены после воспроизведения повторных запросов. Генератор CSS сохраняет базовые стили и резервное начертание, не создавая второго источника загрузки.

Обновлено 19 октября 2026 года: обычный QCF V2 переведён на отдельные шрифты каждого аята из `public/fonts/qcf-ayah-v2`. Все 6236 файлов уже нарезаны скриптом `scripts/trial-qcf-ayah-subsets.py`. Вместо всей страницы для `22:27` загружается только `/fonts/qcf-ayah-v2/22-27.woff2`. Коды, контуры и метрики сохранены; обычный Unicode, переводы и аудио не менялись. Цветной V4 (`-T`) остаётся постраничным: монохромные фрагменты V2 не заменяют цветные шрифты.

Проверка перехода: все 6236 файлов прошли проверку манифеста и SHA-256; тесты рендерера и загрузчика, точечная проверка TypeScript и серверного HTML прошли без сборки. В локальном Edge проверены «Азан», «Аврат», урок 40 и V4 в «Муаллим сани», переход «Азан - список - Аврат - список - Азан» без повторной загрузки готовых аятов. Контрольные снимки с нарезанными и исходными шрифтами совпали пиксель в пиксель для 2:1-7, 22:27, 1:1, 1:2, повторного 1:1 и отдельного знака суджуда. Файл 22:27 уменьшился со 180 792 до 21 240 байт, 9:3 - со 131 448 до 33 516 байт. Это сравнение файлов; новый результат LCP в PageSpeed пока не измерен.

Дополнение 19 октября 2026 года: загрузчик QCF перенесён из общего отложенного модуля в серверный HTML. Аяты текущей страницы доступны загрузчику при разборе ответа, а внешние скрипты не задерживают запросы шрифтов. Сохранены загрузка нижних аятов при приближении к экрану, один запрос на файл, Unicode до готовности и обработка динамических вставок. В Edge с заблокированными внешними скриптами проверено: 22:27 на «Азане» уже выводится в QCF при четырёх ещё не запущенных островах Astro. Контрольный дальний аят не запрашивается до прокрутки; повторное включение загрузчика не создаёт второго запроса или второго набора правил. Модульные тесты дополнены запуском до появления `<body>`, ожиданием пересечения экрана и поздним приходом текста глифов.

Добавлен параметр `-T` для цветного таджвида QCF V4: `{Quran}2:255-T{/Quran}`. Обычные и цветные шрифты теперь хранятся локально и загружаются браузером с сервера сайта по мере необходимости. Официальный CDN Quran Foundation используется только скриптом подготовки для скачивания или обновления файлов.

**Принятое решение после визуального сравнения:** для обычных аятов сохраняем QCF V2; QCF V4 используем только при суффиксе `-T`. Монохромный V4 для обычных аятов не используем. Временная страница сравнения удалена.

В курсе «Муаллим сани» ко всем тегам `{Quran}` добавлен `-T`, поэтому аяты курса выводятся с цветным таджвидом V4. Отдельные подписи с названием суры и номером аята перед тегами убраны: источник уже выводит сам рендерер. В остальных курсах выбор шрифта по-прежнему определяется наличием `-T` в конкретном теге.

## 1. Общая схема

В тексте урока пишем:

```text
{Quran}2:255{/Quran}
{Quran}2:1-7{/Quran}
{Quran}2:255-T{/Quran}
{Quran}2:1-7-T{/Quran}
```

Первые два тега - один аят и диапазон аятов одной суры. Суффикс `-T` перед закрывающим тегом включает цветные правила таджвида для одного аята или всего диапазона.

| Тег | Шрифт |
| --- | --- |
| `{Quran}2:255{/Quran}` или `{Quran}2:1-7{/Quran}` | QCF V2, обычное начертание |
| `{Quran}2:255-T{/Quran}` или `{Quran}2:1-7-T{/Quran}` | QCF V4, цветной таджвид |

```text
Текст урока с тегом {Quran}
    ↓ replaceQuranTags.ts
renderAyahBlock / renderAyahRangeBlock
    ↓ данные из локальных JSON
HTML: арабский текст + скрытые QCF-коды + перевод + кнопка аудио
    ↓ qcfFontLoader.js в серверном HTML загружает шрифт аята V2 или страницы V4
Арабский Unicode заменяется начертанием QCF после готовности шрифта
```

Парсер и рендерер используются как при выводе страниц Astro, так и в компонентах React. Часть аятов может появляться позже - например, при открытии теории или словаря. Поэтому загрузчик шрифтов следит и за добавлением нового содержимого.

Посетителю не требуется отдельный запрос к Quran API за каждым аятом: тексты и коды уже лежат в проекте. Браузер получает файлы обычных и цветных шрифтов с сервера сайта, по мере необходимости; обращения к внешнему CDN при чтении аятов нет.

### Почему для одного текста нужны две версии

- **Арабский Unicode** - обычный читаемый текст из `quran-uthmani-hafs.json`. Он виден сразу, остаётся при ошибке загрузки и используется программами чтения с экрана.
- **QCF `code_v2`** - специальные коды глифов из `quran-qcf-v2.json`. Они дают нужное начертание только вместе с соответствующим шрифтом аята, нарезанным из его страницы мусхафа (или исходным цветным шрифтом страницы V4).

Без правильного QCF-шрифта коды могут выглядеть как посторонние символы, квадраты или неправильный текст. Их нельзя показывать обычным запасным шрифтом в ожидании загрузки.

WOFF2 меняет способ хранения и передачи шрифта, а не систему кодирования аятов. Мы скачали готовые официальные QCF v2 WOFF2 без самостоятельного преобразования файлов. В скачанном наборе суммарный размер 604 файлов уменьшился примерно на 53% по сравнению с прежними TTF. Это уменьшает объём передачи, но не гарантирует меньшего времени в каждом отдельном замере: влияют кеш и условия загрузки.

## 2. Файлы и их роли

### 2.1. Данные

| Файл | Что хранит |
| --- | --- |
| `src/data/quran-qcf-v2.json` | Ключ `сура:аят` → номер страницы и QCF-коды |
| `src/data/quran-uthmani-hafs.json` | Читаемый арабский Unicode |
| `src/data/quran-hamza-wasl-all.json` | 10 772 слова с хамзой васль; флаг `is_start` выделяет 265 начал чтения для основного режима |
| `src/data/quran-hamza-wasl-qcf.json` | Проверенные границы Unicode и QCF-кодов для всех 10 772 слов |
| `src/data/quran-kuliev-ru.json` | Русский перевод Кулиева |
| `src/data/surahs.json` | Названия и метаданные сур |
| `src/data/qcf-v2-woff2-manifest.json` | Источники, размеры и SHA-256 исходных шрифтов страниц V2 для нарезки |
| `public/fonts/qcf-ayah-v2/manifest.json` | Все 6236 фрагментов: ссылка аята, страница, размер, SHA-256 файла, кодов и исходного шрифта; результат проверки контуров и метрик |
| `src/data/qcf-v4-woff2-manifest.json` | Источник и SHA-256 общего набора цветного таджвида COLRv1: 604 страницы |

Карта QCF выглядит так; многоточие здесь обозначает сокращённый пример, не реальные данные для вставки:

```json
{
  "2:222": {
    "page": 35,
    "code_v2": "…"
  }
}
```

`page` - страница мусхафа, от 1 до 604. Это **не номер суры и не номер страницы сайта**. `code_v2` - строка кодов именно для шрифта этой страницы.

Арабский текст находится в `quran["quran-uthmani-hafs"]`, перевод - в `quran["ru.kuliev"]`. Записи содержат поля:

```ts
{ id: number, surah: number, ayah: number, verse: string }
```

15 октября 2026 года для единообразия из записей `95:1` и `97:1` удалена предшествующая басмала: поле `verse` содержит только текст соответствующего аята. Остальные буквы и огласовки этих аятов сохранены; басмала `1:1` остаётся на месте. В официальной выгрузке Tanzil басмала может находиться в одной строке с первым аятом суры; шадда над `ب` перед сурами 95 и 97 обозначает идгам при соединении с концом предыдущей суры, а не ошибку источника. Объяснение: [Tanzil - A Note on Bismillah](https://tanzil.net/docs/a_note_on_bismillah). При повторном импорте нужно учитывать отделение вступительной басмалы в данных сайта.

В `quranRenderer.ts` из них строятся карты по одинаковому ключу:

```ts
arabicMap["2:222"]       // арабский Unicode
translationMap["2:222"]  // перевод
qcfMap["2:222"]          // { page, code_v2 }
```

`arabicMap` теперь участвует в обычном выводе: это текст до загрузки шрифта и при её ошибке. Его нельзя удалять как неиспользуемые данные.

Метаданные суры в `surahs.json` включают `num`, `arabic_name`, `name_ru`, `meaning_ru`, `ayahs`, `start`, `type`, `rukus`. Для подписи источника используются `name_ru` и `meaning_ru`.

### 2.3. Шрифты и стили

Основной набор V2 теперь состоит из отдельных аятов:

```text
public/fonts/qcf-ayah-v2/1-1.woff2
public/fonts/qcf-ayah-v2/2-222.woff2
public/fonts/qcf-ayah-v2/114-6.woff2
public/fonts/qcf-ayah-v2/manifest.json
```

В браузере путь начинается с `/fonts/`, без `public`. Привязка определяется номером суры и аята, а не только страницей:

| Аят | Семейство | Атрибут готовности | Файл |
| --- | --- | --- | --- |
| 1:1 | `QCFA1-1` | `data-qcf-ayah="1-1"` | `1-1.woff2` |
| 2:222 | `QCFA2-222` | `data-qcf-ayah="2-222"` | `2-222.woff2` |
| 114:6 | `QCFA114-6` | `data-qcf-ayah="114-6"` | `114-6.woff2` |

Семейство V2: `QCFA${surah}-${ayah}`. У разных аятов одной страницы разные семейства и правила готовности. Повторения одного аята в уроке, словаре и динамически вставленных блоках используют один запрос в пределах документа и обычный HTTP-кеш между страницами.

`data-qcf-page` и `.qcf-page-N` сохранены как метаданные происхождения кодов. Они больше не определяют шрифт V2. Для V4 по-прежнему используются `QCFT${page}`, `data-qcf-variant="tajweed"` и файл `/fonts/mushaf-v4-woff2/colrv1/p${page}.woff2`.

Исходные 604 файла `public/fonts/mushaf-v2-woff2/pN.woff2` нужны для повторной нарезки. Браузер их больше не запрашивает; автоматического возврата к большому файлу при ошибке фрагмента нет. При ошибке остаётся Unicode и возможен повтор загрузки того же фрагмента.

Генератор `scripts/generate-qcf-v2-css.mjs` записывает только базовые стили. Статических `@font-face` нет: единственный владелец шрифтов и правил готовности - `qcfFontLoader.js`. После готовности точного `FontFace` он скрывает Unicode и показывает QCF только для соответствующего аята V2 или страницы V4.

В `src/styles/tailwind.css` импорт должен оставаться в начале, до остальных правил:

```css
@import "./qcf-v2.css";
```

`.qcf-ayah` задаёт направление справа налево, выравнивание и базовые размеры, но **не семейство страницы**. Загрузчик назначает семейство только вложенному `.qcf-glyphs` после готовности файла. Иначе запасной Unicode тоже попадёт под QCF-шрифт и станет нечитаемым.

Внешний вид блока и дополнительные настройки размера находятся также в `tailwind.css`, в правилах `.quran-ayah-block__arabic` и соседних классов. Они могут переопределять базовый размер из `qcf-v2.css`.

Сгенерированный CSS лучше менять через `generate-qcf-v2-css.mjs`, иначе следующая генерация затрёт ручную правку.

Прежний набор TTF находится в `public/fonts/mushaf-v2/QCF2001.ttf` … `QCF2604.ttf`. Сайт его больше не использует; при публикации текущего рендерера переносить этот набор не требуется. Это файлы предыдущей реализации, а не запасной источник для загрузчика WOFF2.

### 2.4. Рендерер и парсер тегов

`src/utils/quranRenderer.ts` импортирует локальные JSON с атрибутом типа:

```ts
import qcfV2Data from "../data/quran-qcf-v2.json" with { type: "json" };
```

Это актуальный вариант импорта. Старые примеры с `?json` не описывают текущую реализацию.

Основные функции:

| Функция | Результат |
| --- | --- |
| `getQcfV2ForAyah(surah, ayah)` | `{ page, code_v2 }`; ошибка, если записи нет |
| `getAyahText(surah, ayah)` | Арабский текст и перевод; ошибка при отсутствии перевода |
| `renderAyahBlock(surah, ayah)` | HTML одного аята |
| `renderAyahRangeBlock(surah, from, to)` | HTML диапазона с отдельным шрифтом для каждого аята V2 |

Подпись источника формируется так:

```ts
const sourceLine = `${surahNameRu}-${surahMeaningRu}, ${surah}:${ayah}`;
// Например: аль-Бакара-Корова, 2:222
```

Путь аудио строится из трёхзначных номеров суры и аята:

```text
2:222 → /mp3/002/002222.mp3
```

Текущий блок содержит арабский текст, перевод и кнопку прослушивания с подписью источника. Аят выводится шрифтом, отдельной PNG-картинки аята в этой реализации нет.

В текстовых уроках, включая «Учебник 6 столпов», статью выводит `src/components/blog.tsx`. Это обычный `<article>`, видимый уже в серверном HTML, без ожидания запуска React. Раньше анимация `motion.article` задавала `opacity: 0`: при медленной загрузке скриптов пользователь видел навигацию и пустое место, затем весь текст сразу с уже готовыми QCF. Не возвращать начальное скрытие основного содержимого. Перед вставкой HTML переносы CRLF/CR приводятся к LF, как при разборе HTML браузером, чтобы они не создавали несовпадение при гидратации.

Упрощённый пример HTML одного аята; иконки и оформительские классы опущены:

```html
<div class="quran-ayah-block" data-quran-ayah="one_verse"
     data-surah="2" data-ayah="222" data-page="35">
  <p class="quran-ayah-block__arabic qcf-ayah" lang="ar" dir="rtl">
    <span class="qcf-text" data-qcf-page="35" data-qcf-ayah="2-222" lang="ar" dir="rtl">
      <span class="qcf-fallback" aria-hidden="true">…арабский Unicode…</span>
      <span class="qcf-glyphs qcf-page-35" aria-hidden="true">…code_v2…</span>
      <span class="sr-only">…арабский Unicode…</span>
    </span>
  </p>
  <div class="quran-ayah-block__translation">…перевод…</div>
  <div class="quran-ayah-block__audio">
    <button class="quran-audio-button" data-audio-id="quran-audio-2-222">
      <span class="quran-ayah-block__source">аль-Бакара-Корова, 2:222</span>
    </button>
    <audio id="quran-audio-2-222" class="quran-audio-element" preload="none">
      <source src="/mp3/002/002222.mp3" type="audio/mpeg" />
    </audio>
  </div>
</div>
```

`renderQcfText` создаёт три вложенных элемента: видимый запасной Unicode, скрытые QCF-коды и Unicode для программы чтения с экрана. Последний остаётся доступен независимо от готовности шрифта; два визуальных варианта имеют `aria-hidden="true"`, чтобы текст не читался дважды.

Текст, перевод, подписи и QCF-коды проходят через `escapeHtml`. Это защищает HTML и не меняет последовательность кодов, которую браузер получает как текст. Не нужно отменять экранирование ради QCF.

`src/utils/replaceQuranTags.ts` ищет теги регулярным выражением:

```ts
/\{Quran\}(\d+):(\d+)(?:-(\d+))?(-T)?\{\/Quran\}/gi
```

Без диапазона или при одинаковых границах вызывается рендерер одного аята. При ошибке исходный тег остаётся в тексте, а причина записывается в консоль. Видимый `{Quran}…{/Quran}` - повод проверить номер аята и наличие данных.

### 2.5. Диапазоны и границы страниц

Для `{Quran}2:1-7{/Quran}` каждый из семи аятов получает собственный `qcf-text`, `data-qcf-ayah="2-1"` ... `data-qcf-ayah="2-7"` и свой шрифт V2. Между аятами сохраняется пробел; весь диапазон остаётся одним арабским абзацем. Объединять разные аяты в один элемент с одним фрагментом шрифта нельзя, даже если они находятся на одной странице мусхафа.

В V4 отдельные аяты и части с подсказками васля используют общий шрифт своей страницы. Метаданные `data-pages` сохраняют список страниц в порядке следования. Для 2:1-7 это страницы 2 и 3.

Отдельный знак суджуда использует глиф из 84:21 и тот же файл `84-21.woff2`, а не полную страницу 589. При наличии самого аята запрос переиспользуется.

Переводы выводятся отдельными строками с номерами аятов. Аудиофайлы идут по порядку в `data-playlist` элемента `<audio>`. Обратные границы нормализуются: 2:7-1 выводится как 2:1-7.

### 2.6. Безопасная загрузка шрифтов

`src/layouts/Base.astro` вставляет `src/utils/qcfFontLoader.js` непосредственно в `<head>` через `<script is:inline data-qcf-bootstrap>`. Исходник импортируется как `?raw`, экспорт функции убирается, функция запускается внутри замыкания. Это один и тот же загрузчик, а не две разные реализации. `src/utils/qcfFonts.ts` сохраняет модульный экспорт для тестов и других вызовов; повторный запуск в одном документе ничего не создаёт.

Загрузчик запускается при разборе HTML, не ожидая выполнения внешних модулей, React и Mermaid. Он следит за корневым элементом документа: `<body>` может ещё не существовать, а обёртка аята и её дочерний текст могут прийти разными частями ответа. Серверный HTML уже содержит `data-qcf-ayah` или данные страницы V4 для каждого выведенного аята; по ним вычисляется точный адрес файла. Отдельного запроса за списком шрифтов нет.

Шрифты видимой и ближайшей области начинают загружаться сразу после появления аятов и расчёта их положения. Остальные ждут прокрутки (`rootMargin: "100% 0px"`, запас в один экран); все шрифты статьи одновременно не скачиваются. Для скрытых теорий и других статей загрузка начинается только после появления соответствующих элементов. Предзагрузка всех файлов через `preload` и статические `@font-face` не добавлялись: единственный владелец файлов по-прежнему `FontFace` загрузчика.

Порядок работы:

1. CSS изначально скрывает `.qcf-glyphs`; `.qcf-fallback` виден.
2. Загрузчик находит элементы с `data-qcf-page` и читает QCF-коды из вложенного элемента.
3. Для аята 2:222 читает `data-qcf-ayah="2-222"`, создаёт собственный `FontFace` с семейством `QCFA2-222` и адресом `/fonts/qcf-ayah-v2/2-222.woff2`, затем вызывает `face.load()`. Для V4 используется номер страницы и прежний цветной файл.
4. Проверяет статус `loaded` и регистрирует готовый шрифт через `document.fonts.add(loadedFace)`.
5. Добавляет CSS, который для этого аята V2 (или страницы V4) скрывает Unicode и показывает QCF. Готовность одного аята не распространяется на соседние аяты той же страницы.

Одного `font-display: block` недостаточно для всей защиты: ключевой механизм - явное скрытие кодов до подтверждённой готовности конкретного шрифта.

Почему не используется прежний `document.fonts.load(...)`: он находил шрифты, связанные с правилами `@font-face` в CSS. В режиме разработки Astro/Vite заменяет начальные стили страницы после загрузки клиентских модулей. При медленной сети в Firefox наблюдалось зависание переключения: WOFF2 уже скачаны, но запрошенные ранее CSS-объекты заменены, текущие шрифты снова имеют статус `unloaded`, а правила показа QCF остаются пустыми. Собственный объект `FontFace` загружается независимо от замены таблицы стилей и после регистрации сохраняется в наборе шрифтов документа.

В сгенерированном CSS нет определений `@font-face`: они создавали повторные запросы. Классы страниц оставлены в HTML только как метаданные; семейство назначает загрузчик.

Состояния запросов хранятся по ключам `v2-сура-аят` и `v4-страница`. Несколько блоков одного аята V2 используют общий запрос. Новый аят той же страницы получает отдельный запрос и остаётся на Unicode до готовности своего файла. Правило готовности действует и на новые копии того же аята; смена темы не требует другого файла. Загрузка начинается при приближении блока к экрану: `IntersectionObserver` с `rootMargin: "100% 0px"`. Без этого API загрузка начинается сразу.

`MutationObserver` следит за добавленными элементами, поэтому аяты из раскрываемых разделов тоже получают нужные шрифты. Загрузчик добавляет правила CSS в `<head>`, не переписывая HTML внутри компонентов React: это позволяет избежать конфликтов при гидратации.

При ошибке Unicode остаётся видимым, а неудачная запись запроса удаляется. Повтор возможен при событии восстановления соединения `online` или появлении новой копии этого аята (или страницы V4). Постоянного повтора по таймеру нет.

Если JavaScript отключён или браузер не поддерживает Font Loading API, остаётся обычный арабский текст.

### 2.7. Цветной таджвид: параметр `-T`

```text
{Quran}2:255-T{/Quran}
{Quran}2:1-7-T{/Quran}
```

Отдельного тега `QuranT` нет. Парсер передаёт `{ tajweed: true }` в `renderAyahBlock` или `renderAyahRangeBlock`. Перевод, ссылка на суру и аудио сохраняются; для обычного и цветного блока одного аята используются разные идентификаторы аудио.

QCF V4 использует ту же карту `code_v2` и страниц из `quran-qcf-v2.json`. Повторно получать тексты аятов не требуется. Отличается шрифт, которым показаны эти коды. В HTML цветного блока добавлен `data-qcf-variant="tajweed"`, а класс кодов - `qcf-tajweed-page-N`. Класс обычного шрифта `qcf-page-N` этому блоку не назначается.

Загрузчик использует локальные копии официальных WOFF2. Файлы лежат в `public/fonts/mushaf-v4-woff2`, а браузер запрашивает:

```text
Все браузеры, включая Firefox:
/fonts/mushaf-v4-woff2/colrv1/p{PAGE}.woff2
```

Для COLRv1 создаётся семейство `QCFTN` и правила `@font-palette-values`: палитра 0 для светлой темы, 1 для тёмной. Переключение класса `dark` у `<html>` меняет палитру без скачивания второго файла. Это общий механизм для всех браузеров, включая Firefox; отдельного определения браузера и наблюдателя за темой нет.

**Настройка цветов через CSS.** Общий формат QCF V4 COLRv1 позволяет задавать собственные цвета таджвида через дескриптор `override-colors` внутри `@font-palette-values`. Он переопределяет цвета по индексам палитры шрифта; перед настройкой нужно установить соответствие этих индексов нужным элементам и правилам таджвида. Нужная палитра применяется свойством `font-palette`. Правила для каждого семейства `QCFTN` формируются в `src/utils/qcfFontLoader.js` - там можно добавить собственные переопределения для светлой и тёмной тем.

Сейчас используются встроенные палитры 0 и 1, собственные цвета ещё не заданы. Для будущей настройки достаточно изменить CSS-палитры: пересобирать или повторно скачивать WOFF2 не требуется. Firefox получает тот же файл COLRv1, что и остальные браузеры; отдельные шрифты для него или для каждой темы больше не нужны.

Готовность v2 никогда не открывает коды V4. Пока шрифт нужной страницы загружается, виден Unicode без цветовой разметки. После загрузки CSS выбирает палитру текущей темы, даже если тема была изменена во время ожидания. Ошибка загрузки сохраняет Unicode; повтор возможен при восстановлении соединения или появлении блока. Это предотвращает показ кодов при медленной сети.

`fonts:download` готовит один общий набор V4: 604 файла COLRv1, около 49 МиБ. Отдельные OT-SVG для Firefox больше не используются и не скачиваются. При публикации нужно перенести каталог `fonts/mushaf-v4-woff2/colrv1` вместе с обычными шрифтами. На страницах без `-T` запросов V4 нет; даже с `-T` браузер скачивает только нужные страницы.

Современный Firefox поддерживает COLRv1 и CSS-палитры начиная с версии 107 ([Mozilla](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/107#css)). Поэтому используем общий формат. Автоматические тесты проверяют выбор файла и палитр, в том числе с идентификатором Firefox; правильность отображения конкретного шрифта нужно также проверить в самом Firefox в обеих темах.

### 2.9. Хамза васль в начале чтения: подсказки только для `-T`

Добавлено 12 октября и расширено 13 октября 2026 года. В цветном аяте огласованное слово в небольшой контрастной плашке стоит **непосредственно перед оригинальным словом**. Например, `{Quran}1:6-T{/Quran}` показывает `اِهۡدِنَا` перед исходным `ٱهۡدِنَا`. Поясняющих подписей «При начале…» и отдельных строк под аятом больше нет. Плашки относятся к началу чтения с выбранного слова: в начале аята либо после указанных ниже знаков остановки; при слитном чтении хамза васль не произносится.

С 18 октября 2026 года используется единый `src/data/quran-hamza-wasl-all.json`: **10 772 записи в 4458 аятах**, **2004 варианта написания**. Поле `is_start: true` выделяет основной режим: **265 записей в 258 аятах**, **87 вариантов написания слова**. Это 231 первое слово аята и 34 слова после знаков остановки. Остальные 10 507 записей имеют `is_start: false` и показываются в режиме «Все слова с хамзой васль». Отдельный файл основного списка удалён. Все слова, огласовки, номера и порядок сохранены. Поля каждой записи:

```json
{
  "surah": 1,
  "ayah": 6,
  "word_number": 1,
  "word": "ٱهۡدِنَا",
  "reading": "اِهۡدِنَا",
  "is_start": true
}
```

`is_start` означает начало чтения в основном режиме, включая слова после остановок; это не только проверка `word_number === 1`. Рендерер выбирает область подсказки прямо по этому флагу.

`word_number` - номер слова от начала аята, начиная с 1. Присоединённые `وَ` / `فَ` не отделяются в новые слова; служебные знаки руб‘а, саджда и остановки не увеличивают номер. `word` - выбранное слово из `quran-uthmani-hafs.json` без служебных знаков остановки; `reading` - учебная запись для начала чтения. Обычно в ней только начальная `ٱ` заменена на `ا` с фатхой, кясрой или даммой. В **46:4:18** слово `ٱئۡتُونِي` записано как `اِيتُونِي`: при начале вторая хамза с сукуном заменяется на йа мадда, получается долгое «и». Сам текст аята, Unicode для запасного вывода и QCF-коды не заменяются.

Отбираются слова, непосредственно начинающиеся с `ٱ`, если это первое слово аята либо перед ним стоит один из пяти знаков из урока `theory/39_vakf.md`. Поиск проводится по настоящим Unicode-символам в исходном тексте, а не по условному написанию знака обычными буквами:

| Знак | Unicode | Всего в исходном тексте | Следом слово с хамзой васль |
| --- | --- | ---: | ---: |
| мим - обязательная остановка `ۘ` | U+06D8 | 21 | 3 |
| джим - остановка дозволена `ۚ` | U+06DA | 2076 | 15 |
| «саля» - продолжение предпочтительнее `ۖ` | U+06D6 | 1651 | 10 |
| «каля» - остановка предпочтительнее `ۗ` | U+06D7 | 518 | 6 |
| парные троеточия `ۛ` | U+06DB | 6 | 0 |

Всего проверено 4272 таких знака. Для парных троеточий учитывается условие остановки у одного из пары; в текущем файле сразу после них слов с `ٱ` нет. Знак запрета остановки и знак сакта не входят в этот отбор. Не включаются слова с присоединёнными `وَ` / `فَ`, внутренние хамзы без подходящего предшествующего знака и буквенные начала вроде `الٓمٓ`. Огласовки в JSON заданы явно: 197 записей с фатхой, 45 с кясрой, 23 с даммой. При обновлении исходного текста нужно заново проверить отбор и огласовки, затем выполнить точечный тест.

Обозначения Unicode сверены с [официальной таблицей символов Arabic](https://www.unicode.org/Public/18.0.0/charts/nameslist/0600/); значения знаков - с [About Tajweed, разбором знаков остановки](https://www.abouttajweed.com/080602.htm).

Основание выбора огласовок: [About Tajweed - глаголы и исходная огласовка третьей буквы](https://www.abouttajweed.com/tajweed-rules/56-hamzah-al-wasl/71-hamzah-al-wasl-lesson-3), [отглагольные имена](https://www.abouttajweed.com/tajweed-rules/56-hamzah-al-wasl/72-hamzah-al-wasl-lesson-4), [определённый артикль](https://www.abouttajweed.com/tajweed-rules/56-hamzah-al-wasl/74-hamzah-al-wasl-lesson-6).

Уникальный ключ записи - `сура:аят:номер_слова`. Рендерер группирует полный список по `сура:аят` и вставляет подсказки перед соответствующими словами, помечая основные как `data-wasl-scope="basic"`, остальные - как `all`. По умолчанию CSS показывает только основные. Например, у 24:35 основные слова 1, 10 и 13; они не перезаписывают друг друга. Номера остаются в JSON и атрибутах HTML, но не выводятся в плашке. У обычного тега без `-T` подсказок нет. В диапазонах плашки также стоят внутри арабского текста перед своими словами.

Считать пробелы QCF как номера слов нельзя: знаки остановки и руб‘а могут иметь отдельные глифы. Поэтому `src/data/quran-hamza-wasl-qcf.json` хранит для каждого из 10 772 мест `start` / `end` - границы в исходной строке `code_v2`, `code` - проверенные глифы, `unicodeStart` / `unicodeEnd` - границы исходного Unicode. Границы получены из пословных данных Quran.com (`words=true`, `word_fields=code_v2,text_uthmani`), со сверкой всех исходных кодов, страниц и последовательностей букв **6236 аятов**. В исходном Unicode местами иначе расставлены пробелы: например, в 2:77 и 5:107. Поэтому номера слов соответствуют проверенному пословному разбиению, а границы сохраняют настоящий текст без переписывания. Основные 265 номеров сохранены. После удаления вступительной басмалы из `97:1` границы Unicode для слова `97:1:5` («ٱلۡقَدۡرِ») смещены на 39 символов: `unicodeStart: 34`, `unicodeEnd: 43`; QCF-коды и номер слова не изменились. Поля пословных данных описаны в [документации Quran Foundation](https://api-docs.quran.foundation/docs/api/field-reference/).

После изменения исходного текста обновить границы командой `node scripts/update-hamza-wasl-qcf.mjs`, затем сформировать полный список командой `node scripts/update-hamza-wasl-all.mjs` и выполнить `npm run test:qcf`. Первый скрипт читает открытые данные `api.quran.com/api/v4/verses/by_chapter/…` порциями по 50 аятов и записывает карту только после успешной сверки всего Корана; необязательный `--cache-dir` позволяет повторно использовать ответы при подготовке. Второй скрипт берёт слова непосредственно из исходного Unicode по проверенным границам, назначает огласовки и заново вычисляет `is_start` по началам аятов и знакам остановки. Проверенные основные огласовки читаются из того же полного JSON через фильтр `is_start`, отдельный файл больше не нужен. Учтены существительные, шадда при подсчёте третьей буквы, временная дамма, глаголы `ٱلۡتَقَى` и родственные формы, замена второй хамзы с сукуном на букву мадда, а также `ٱلِٱسۡمُ` в 49:11:30. Основание исключений: [About Tajweed, урок 3](https://www.abouttajweed.com/tajweed-rules/56-hamzah-al-wasl/71-hamzah-al-wasl-lesson-3) и [урок 5](https://www.abouttajweed.com/tajweed-rules/56-hamzah-al-wasl/73-hamzah-al-wasl-lesson-5). На сайте импортируются локальные JSON; новых запросов к API или файлов шрифтов при показе аята нет. При несовпадении границ с кодами рендерер сообщает ошибку.

Для `-T` рендерер делит Unicode и QCF-коды на части по этим границам, сохраняя исходную последовательность и пробелы. Плашка и оригинальное слово объединены в `.qcf-wasl-pair`; на узком экране слишком длинная пара может переноситься внутри, чтобы не выходить за границы блока. Каждая часть получает обычный `.qcf-text` с тем же цветным шрифтом страницы V4 и Unicode до готовности шрифта. Загрузчик переиспользует один запрос шрифта для всех частей. Декоративная плашка скрыта от программы чтения с экрана; исходный арабский текст остаётся в `sr-only`.

Подсказка использует обычный Unicode, класс `arab` и уже имеющийся Amiri; новые QCF-шрифты скачивать не нужно. Оформление `.quran-ayah-block__wasl-hint` находится в `src/styles/tailwind.css`: цвета темы инвертированы - светлый фон с тёмным текстом в тёмной теме, тёмный фон со светлым текстом в светлой. Верхний отступ увеличен отдельно от нижнего, чтобы огласовки помещались на фоне плашки.

В правом нижнем углу блока с подсказками находится круглая кнопка со знаком васля **без алифа**. Значок - встроенный SVG с контуром васля из AmiriLocal. Диаметр кнопки 36 пикселей, как у круга проигрывания звука; у обеих общие стили рамки и ореола при наведении. Кнопка выводится только для `-T`, если хотя бы одно слово блока есть в полном списке; у диапазона она одна. Нажатие открывает меню из трёх режимов: **«Выключены»**, **«В начале и после остановок»** (по умолчанию), **«Все слова с хамзой васль»**. Выбор применяется ко всем аятам страницы через атрибут `data-quran-wasl-mode` на корневом элементе. При выключении исходные аяты сохраняются, кнопка остаётся видимой с прозрачным фоном. Меню закрывается после выбора, по Escape и нажатию вне него; фокус после выбора возвращается к кнопке. Обработчик `src/utils/quranWaslHints.ts` подключён в `src/layouts/Base.astro`, учитывает позднее добавленные примеры. На обычных страницах режим не сохраняется после перезагрузки; тестовая страница переносит его в параметры адреса при фильтрации и переходе между страницами. Учебная подсказка не обозначает допустимость остановки или начала чтения в этом месте.

`npm run test:qcf` проверяет основной отбор по пяти знакам, сохранение 265 записей, контрольные огласовки и исключения полного режима. Для всех 10 772 подсказок проверяет границы Unicode/QCF и соседство с исходным словом. Для всех 6236 аятов проверяет сохранность Unicode, QCF-кодов и их порядка, доступный исходный текст, отсутствие подсказок в обычном выводе и правильное разделение основных и дополнительных подсказок, одиночные теги и диапазоны. Тест читает TypeScript напрямую через Node.js, **без сборки Vite/Astro**; используется Node.js 24. Все проверки прошли.

Для визуальной сверки используется `/quran/hamza-wasl-test#wasl-verses` (`src/pages/quran/hamza-wasl-test.astro`). **Таблица и выборка аятов всегда используют полный список из 10 772 слов независимо от режима подсказок.** Без фильтров это 2004 строки с суммой 10 772 вхождения в 4458 аятах. Меню васля меняет только видимость плашек, без перезагрузки страницы и изменения таблицы, фильтров или номера страницы. Фильтры положения («Все слова / В начале / В тексте»), суры и огласовки совместимы. Таблица считает всю отфильтрованную выборку и изначально свёрнута. Аяты выводятся через обычные теги `-T` с переводом и озвучкой, **по 40 на страницу**, с кнопками перехода и выбором номера страницы. Условия проверяются для одного слова; неподходящие плашки скрываются, исходный аят сохраняется полностью. Параметры `mode`, `position`, `surah`, `vowel`, `page` сохраняют состояние в адресе; прежний `scope` игнорируется. «Сбросить» очищает три фильтра, сохраняя режим. Идентификаторы аудио не дублируются. Страница помечена `noindex, nofollow`, не включена в меню и карту сайта; её можно удалить отдельно от данных и подсказок рендерера.

Сводная таблица использует те же фильтры: исходное написание, слово с огласовкой для начала чтения и количество вхождений в текущую выборку. После фильтрации количества пересчитываются, пустые строки скрываются, оставшиеся сортируются по убыванию количества. «Все слова» даёт 87 вариантов и 265 вхождений в 258 аятах; «В начале» - 75 вариантов и 231 вхождение в 231 аяте; «В тексте» - 21 вариант и 34 вхождения в 31 аяте. Группировка учитывает точную пару `word` / `reading`: различия в огласовках и коранических знаках не удаляются. Таблица рассчитывается из того же JSON, отдельная копия данных не создаётся. Счётчики показывают число выбранных слов и аятов; при отсутствии совпадений выводится сообщение.

## 3. Источник WOFF2 и условия использования

Официальный источник QCF v2 Hafs:

```text
https://verses.quran.foundation/fonts/quran/hafs/v2/woff2/p{PAGE}.woff2
```

Официальные источники цветного таджвида V4 (скрипт скачивает готовые WOFF2 без преобразования):

```text
https://verses.quran.foundation/fonts/quran/hafs/v4/colrv1/woff2/p{PAGE}.woff2
```

`PAGE` - 1…604. Для обычного `{Quran}` используется версия v2; не подменять её шрифтами v1. Цветной V4 выбирается отдельно параметром `-T`, как описано в §2.7.

Ссылки для повторной проверки:

- [Документация Quran Foundation о шрифтах и CDN](https://api-docs.quran.foundation/docs/tutorials/fonts/font-rendering/#font-files--cdn).
- [Условия использования для разработчиков](https://api-docs.quran.foundation/legal/developer-terms/).

При переходе на WOFF2 в документации были указаны условия локального хранения: активный аккаунт в Developer Console и доступное упоминание Quran Foundation. Упоминание «Шрифты Корана предоставлены Quran Foundation» добавлено на страницу «О проекте» (`src/pages/about.astro`). Наличие аккаунта эта реализация не проверяет. Перед будущим изменением способа распространения следует свериться с актуальными условиями по ссылке; шрифты используются здесь как часть сайта.

Загрузчик сохраняет источник, размер и SHA-256 каждой копии в манифест. Проверка подтверждает совпадение локальных файлов с манифестом; сама контрольная сумма не является отдельным подтверждением происхождения файла.

## 4. Что и как пересобирать

Все команды ниже выполняются из корня проекта. В PowerShell, если запуск `npm.ps1` запрещён политикой компьютера, использовать `npm.cmd` вместо `npm`.

### 4.1. Новый компьютер или подготовка к публикации

```sh
npm run fonts:download
python -m pip install -r scripts/requirements-qcf-subsets.txt
python scripts/trial-qcf-ayah-subsets.py
npm run fonts:check
node scripts/generate-qcf-v2-css.mjs
```

Папка `public/` с медиа исключена из Git правилами проекта. Наличие кода и манифеста в репозитории не означает наличия файлов шрифтов на другом компьютере. Их нужно скачать и включить в публикуемый сайт.

Загрузчик проверяет уже имеющиеся копии и скачивает недостающие или не совпадающие с манифестом. Проверяются сигнатура WOFF2 (`wOF2`), длина, размер и SHA-256.

В `package.json` настроен `prebuild`: обычный `npm run build` перед сборкой проверяет 1208 исходных файлов (604 V2 + 604 V4) и 6236 фрагментов V2 с манифестом. Если шрифты отсутствуют или повреждены, проверка останавливает сборку с подсказкой. Прямой запуск `astro build` обходит этот npm-хук; тогда проверку нужно выполнить отдельно.

### 4.2. Обновить официальные файлы шрифтов

```sh
npm run fonts:download -- --refresh
python scripts/trial-qcf-ayah-subsets.py --resume
npm run fonts:check
npm run test:qcf
```

`--refresh` заново скачивает оба официальных набора и обновляет манифесты. После изменения исходников заново нарезать аяты и проверить результат. Для браузера опубликовать `fonts/qcf-ayah-v2` с манифестом и `fonts/mushaf-v4-woff2`; постраничный V2 нужен на машине подготовки для нарезки. При длительном кешировании на сервере сбросить кеш обновлённых файлов.

### 4.2.1. Нарезать V2 по аятам

```sh
python -m pip install -r scripts/requirements-qcf-subsets.txt
python scripts/trial-qcf-ayah-subsets.py
npm run fonts:check-ayahs
```

По умолчанию обрабатываются все 604 страницы и 6236 аятов. Имена файлов - `сура-аят.woff2`, без ведущих нулей. Скрипт сохраняет контуры, метрики, исходные QCF-коды и проверяет каждый результат перед включением в манифест. Исходные файлы не меняются.

Для прерванного запуска или обновления исходных файлов использовать `--resume`: исправные результаты из совместимого манифеста переиспользуются, устаревшие перегенерируются. Если изменились карта кодов, версия FontTools или настройки, скрипт требует новый каталог; сохранить прежний результат отдельно, создать полный новый набор и заменить его после проверки. `--pages` и `--ayahs` подходят для диагностики, но частичный набор не годится для публикации всего сайта. `--check` проверяет только исходники и не подтверждает готовность нарезки; для этого служит `fonts:check-ayahs`.

Общий набор может занимать больше места на диске, чем 604 исходных файла: общие таблицы повторяются. Выигрыш при чтении отдельной страницы определяется суммой файлов реально показанных аятов, а не размером всего каталога. Процент экономии и время загрузки зависят от выбранных аятов и количества запросов.

### 4.3. Обновить карту QCF-кодов

Это отдельная операция, для которой нужны Python и библиотека `requests`:

```sh
python src/utils/build_quran_qcf_v2.py
npm run test:qcf
```

Скрипт запрашивает `/verses/by_chapter/{chapter}` с полями `code_v2,v2_page` и записывает `src/data/quran-qcf-v2.json`.

Не запускать его только ради смены TTF на WOFF2: для этого коды не менялись. Скрипт может записать неполную карту после ошибок запросов, поэтому сообщение о завершении само по себе не подтверждает полноту. Проверить наличие всех 6236 аятов тестом, просмотреть изменения данных и сравнить начертание перед использованием результата. Этот скрипт не обновляет перевод и Unicode-текст.

### 4.4. Изменить путь к шрифтам или базовые стили QCF

Путь V2 `/fonts/qcf-ayah-v2/${ayah}.woff2` и путь V4 меняются в `src/utils/qcfFontLoader.js`. Базовые стили меняются в CSS-шаблоне `scripts/generate-qcf-v2-css.mjs`, затем выполнить:

```sh
node scripts/generate-qcf-v2-css.mjs
```

Семейства и правила готовности определяет только `qcfFontLoader.js`: `QCFA${surah}-${ayah}` для V2, `QCFT${page}` для V4. Не назначать подмножество аята всему классу страницы.

### 4.5. Изменить подпись источника или HTML блока

Подпись меняется в `quranRenderer.ts` в **обеих** функциях рендеринга. Например, вместо дефиса между названием и значением можно использовать скобки:

```ts
const sourceLine = `${surahNameRu} (${surahMeaningRu}), ${surah}:${ayah}`;
```

Для диапазона сохраняется `rangeText` вместо одиночного `${surah}:${ayah}`.

При правке разметки сохранить:

- `qcf-text`, `data-qcf-page`, `data-qcf-ayah` для V2, `data-qcf-variant="tajweed"` для V4, `qcf-fallback`, `qcf-glyphs` - для загрузки и переключения шрифта;
- Unicode и `sr-only` - для читаемости и доступности;
- `quran-audio-button`, `data-audio-id`, соответствующий `id` аудио и `data-playlist` диапазона - для управления звуком;
- экранирование текстовых данных через `escapeHtml`.

### 4.6. Установить текущие изменения на уже работающий сервер

Команды ниже соответствуют схеме из `DEPLOY.md`: код в `/srv/hutba/app`, публичные файлы в `/srv/hutba/assets`, служба systemd называется `hutba`. Если рабочий сервер настроен иначе, подставить его пути и способ перезапуска.

Сначала передать обновлённый код на сервер обычным способом (Git или SFTP), включая `scripts/download-qcf-woff2.mjs`, оба манифеста шрифтов, `package.json` и изменённые файлы `src/`. При передаче через SFTP удалить старую `src/pages/quran/font-comparison.astro`, если она ранее была загружена. Папку `node_modules` с Windows не переносить.

Выполнять от пользователя приложения; следующую команду запускать только после успешного завершения предыдущей:

```bash
cd /srv/hutba/app
npm ci
npm run fonts:download
# Перед проверкой скопировать готовый public/fonts/qcf-ayah-v2 с manifest.json
npm run fonts:check
npm run build
```

Загрузчик подготовит исходные 604 WOFF2 QCF V2 и 604 WOFF2 QCF V4 COLRv1. Он не создаёт фрагменты аятов. Каталог `public/fonts/qcf-ayah-v2` (6236 WOFF2 и `manifest.json`, около 105,30 МиБ без манифеста) нужно передать отдельно либо нарезать на сервере. Уже имеющиеся исправные исходные файлы повторно не скачиваются. На сервере код собирается без большого каталога `public/media`, как описано в `DEPLOY.md`.

После успешной сборки скопировать именно новые каталоги шрифтов в каталог, из которого nginx раздаёт `/fonts/`, и перезапустить сайт:

```bash
mkdir -p /srv/hutba/assets/fonts/qcf-ayah-v2
mkdir -p /srv/hutba/assets/fonts/mushaf-v4-woff2/colrv1
rsync -a --chmod=D755,F644 public/fonts/qcf-ayah-v2/ /srv/hutba/assets/fonts/qcf-ayah-v2/
rsync -a --chmod=D755,F644 public/fonts/mushaf-v4-woff2/colrv1/ /srv/hutba/assets/fonts/mushaf-v4-woff2/colrv1/
sudo systemctl restart hutba
sudo systemctl is-active hutba
```

Ожидается `active`. Проверить доступность обоих вариантов шрифта:

```bash
curl -f -sS -o /dev/null -w 'V2: %{http_code}\n' https://hutba.org/fonts/qcf-ayah-v2/2-255.woff2
curl -f -sS -o /dev/null -w 'V4: %{http_code}\n' https://hutba.org/fonts/mushaf-v4-woff2/colrv1/p42.woff2
```

Оба ответа должны быть `200`. В браузере проверить обычный аят и аят с `-T` в обеих темах. Повторный перенос видео и аудио для этого обновления не требуется. Скрипт `test:qcf` остаётся автоматической проверкой для разработки и не создаёт тестовых страниц на сайте.

## 5. Проверка работы

```sh
npm run test:qcf
npm run fonts:check
```

Первый тест проверяет сохранность кодов и наличие Unicode для всех 6236 аятов в обычном и цветном режиме, разбор параметра `-T`, диапазон через границу страниц, аудио, ожидание шрифта, ошибки и неподтверждённую готовность, замену CSS во время загрузки, повторное использование одного аята и независимую готовность соседних аятов одной страницы, динамический контент и повтор после восстановления соединения. Отдельно проверяются общий файл COLRv1, обе CSS-палитры и отсутствие повторных запросов при смене темы, в том числе с идентификатором Firefox. Это проверка загрузчика, а не запуск настоящего Firefox.

Второй проверяет 1208 исходных WOFF2 по двум манифестам и все 6236 фрагментов V2 по манифесту нарезки, включая хеш карты, коды каждого аята, размеры, сигнатуры и SHA-256 файлов. Отдельная команда только для фрагментов: `npm run fonts:check-ayahs`. Проверки работают без сети и без сборки проекта.

Для ручной проверки открыть обычный урок с аятами при медленной сети: сначала должен быть виден основной текст с читаемым арабским Unicode, затем начертание QCF. При недоступном файле Unicode должен остаться видимым. Проверить также раскрываемую теорию или словарь, где аят добавляется после первоначальной загрузки страницы.

Для таджвида добавить к ссылке на аят или диапазон `-T` и проверить обе темы, в том числе переключение темы во время загрузки в Firefox. На одной странице обычный и цветной варианты одного аята должны загружаться независимо и иметь работающие кнопки аудио.

Проверять следует буквы, огласовки, знаки остановки и номера аятов. Для нескольких страниц мусхафа подходят аяты 1:1, 1:7, 2:1, 2:222, 2:255, 36:1, 55:13, 112:1 и 114:1; для границы страниц - диапазон 2:1-7. Совпадение входных кодов само по себе не доказывает совпадение начертания.

Время загрузки включает получение файла и подготовку шрифта браузером. Замеры нужно проводить при одинаковых условиях сети и кеша. Для этого в инструментах разработчика браузера включить ограничение скорости, отключить кеш и перезагрузить урок.

## 6. Типичные проблемы и где искать причину

| Симптом | Что проверить |
| --- | --- |
| Навигация уже видна, а основной текст появляется только спустя несколько секунд | Не скрыта ли статья через `opacity: 0` до запуска React; это отдельная задержка показа содержимого, даже если QCF уже загружен |
| Вместо аята посторонние глифы или квадраты | Не показан ли `.qcf-glyphs` раньше времени; загружен ли правильный CSS; не назначен ли QCF-шрифт запасному Unicode |
| Текст похож на арабский, но слова не соответствуют аяту | Совпадают ли `data-qcf-ayah="сура-аят"`, семейство `QCFAсура-аят` и файл; для V4 проверить страницу и вариант; не применяется ли фрагмент другого аята |
| Начало диапазона правильное, конец неправильный | Сохранился ли отдельный `qcf-text` и правильный `data-qcf-ayah` у каждого аята V2 |
| Unicode остаётся после загрузки страницы | Ответ WOFF2 в сети, предупреждения `QCF v2-сура-аят` или `QCF v4-страница` в консоли, подключение `initQcfFonts`, статус собственного `FontFace` и содержимое `style[data-qcf-fonts]`; HTTP 200 сам по себе не подтверждает готовность шрифта |
| Аят с `-T` остаётся без цветов | Наличие локальных файлов `fonts/mushaf-v4-woff2/colrv1`, ответы сервера, предупреждения `QCF v4-страница` и палитра `--qcf-light-N` / `--qcf-dark-N`; в Firefox также проверить версию браузера |
| В V4 вокруг огласовок видны тонкие рамки или овалы, например в 2:255 | В исходном V4 `colrv1/p42.woff2` обнаружены отдельные контуры с индексом цвета 14; локальный файл побайтно совпадает с CDN. Эти контуры пока не скрываем и файл не меняем. Обычный тег продолжает использовать V2 |
| В обычном блоке QCF есть, в раскрываемом разделе его нет | Работает ли наблюдение за новыми элементами; сохранились ли `data-qcf-page`, `data-qcf-ayah` (V2) и `.qcf-glyphs` в новом HTML |
| Шрифты работают локально, но не на сервере | Попали ли реальные файлы из игнорируемых Git папок `public/fonts/qcf-ayah-v2` с манифестом и `public/fonts/mushaf-v4-woff2` в публикацию; правильны ли пути и ответы сервера |
| После обновления виден старый результат | Кеш страницы, CSS и шрифта; согласованность опубликованных файлов и манифеста |
| Изменения в `qcf-v2.css` пропадают | Этот файл генерируется: менять исходный шаблон генератора |
| CSS-импорт не работает | `@import "./qcf-v2.css"` должен идти до остальных правил в `tailwind.css` |
| В уроке остался буквальный тег `{Quran}…{/Quran}` | Сообщение парсера в консоли, корректность номера и наличие перевода, QCF, Unicode и метаданных суры |
| Не воспроизводится аудио | Путь вида `/mp3/002/002222.mp3`, наличие файла, связь `data-audio-id` с `id` элемента аудио |

Не составлять общий список запасных семейств `QCF2001, QCF2002, …`: разные страницы содержат разные соответствия кодов глифам. У каждого аята V2 должен быть свой точный фрагмент; у V4 - точный цветной шрифт страницы.

Если возникла ошибка импорта JSON, сначала сравнить код с текущими импортами `with { type: "json" }` и проверить совместимость среды. Возвращать старый суффикс `?json` по прежней заметке не следует.

При дальнейших изменениях обновлять эту памятку вместе с реализацией: сохранять объяснение причин и связей между файлами, а примеры и команды приводить к фактическому состоянию проекта.
