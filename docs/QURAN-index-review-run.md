## Сохранение и проверки

Для каждой партии создать каталог `output/json/quran-index-review-N-M/` с четырьмя файлами: JSON партии, сводный JSON тем 1-M, журнал решений и Markdown-отчёт. Схему и различия оснований сохранять как в партиях 21-30 и 31-40.

После каждой подтемы сохранять выполненные решения и использованные доказательства в материалах текущей партии. Не объявлять недочитанную подтему проверенной. После всей партии проверить: решение для каждой исходной связи, совпадение `verse_keys` и `verse_notes`, точность цитат, наличие ключей и источников, ссылки контекста, отсутствие дублей и сохранность предшествующих тем. Числа в отчёте должны вычисляться по результату. Сохранить SHA-256 источников. Затем обновить прогресс с путями и хешами готовых файлов.

Готовые четыре файла копировать рядом с внешним исходником, используя разрешённую запись и проверку хешей. Если фоновому запуску недоступна запись вне проекта, не терять результат: оставить файлы в проекте и записать `pending_delivery`. Следующую партию начинать только после подтверждения владельца. Не выдавать отсутствие внешней копии за отсутствие проверенных данных.

Не запускать сборку сайта. Не создавать PDF. Не менять код сайта или материалы отдельного чата библиотеки. Использовать обычный дефис вместо длинного и среднего тире в новых текстах.
