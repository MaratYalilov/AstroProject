# Сообщения об ошибках и панель администратора

Реализовано локально 20 октября 2026 года. Публикация и первоначальная настройка на сервере выполняются владельцем.

## Что доступно

В конце обычных уроков, текстовых уроков учебника и интерактивных уроков есть блок «Заметили ошибку?» со ссылкой «Сообщить о неточности». Блок выделен отдельной карточкой: значок помощи у текста и значок сообщения у кнопки. Кнопка использует спокойные голубые оттенки вместо красного предупреждения. На широком экране текст и кнопка расположены в одну строку, на телефоне кнопка переносится под текст. Учтены светлая и тёмная темы.

Ссылка открывает `/feedback/bug`. Адрес и название текущего урока подставляются автоматически. При переключении интерактивного урока используется уже выбранный урок, включая параметры адреса. С JavaScript сохраняется также текущий фрагмент `#...`. Текст ошибки вводится обычным текстом, от 10 до 4000 символов. После успешного сохранения сервер открывает экран «Спасибо за помощь!» (HTTP 303 после POST). Экран оформлен по образцу карточки «Итог урока»: сверху арабская фраза «جزاك اللهُ خيرًا» и перевод «Да воздаст вам Аллах благом!», затем разделительная черта, ниже заголовок благодарности, подтверждение и ссылка возврата. Содержимое по центру, без значка галочки. На нём находится ссылка «Вернуться к уроку» с исходным адресом, параметрами и якорем. Автоматического перехода на урок нет. При обычном переходе в той же вкладке JavaScript запоминает позицию прокрутки в `sessionStorage` и восстанавливает её по нажатию ссылки возврата. Восстановление однократное; начатая пользователем прокрутка или другое взаимодействие отменяет позднюю корректировку при загрузке. При ошибке записи или проверки форма остаётся открытой, сообщает о неудаче и сохраняет введённый текст для повторной отправки. Без JavaScript сохраняются отправка, экран благодарности и ссылка на исходный урок с якорем; позиция в пикселях требует доступного `sessionStorage` и JavaScript. Поле описания в тёмной теме имеет более светлый фон и заметную границу.

Администратор открывает `/admin/feedback` и входит по паролю. В панели есть:

- Счётчики всех, новых, взятых в работу и исправленных обращений.
- Поиск по названию урока, адресу и описанию ошибки, фильтр по статусу, по 25 сообщений на странице.
- Полный текст обращения, ссылка на урок, дата получения в GMT+4.
- Статусы «Новое», «В работе», «Исправлено» и внутренние заметки.
- Выход с отзывом текущей сессии.

Это один административный аккаунт. Новые обращения видны при открытии или обновлении панели; уведомления в почту и Telegram не отправляются. Вложения и ответы посетителю не предусмотрены. Обращения сохраняются на сервере независимо от браузера администратора.

## Локальная настройка

Из корня проекта в интерактивном терминале:

```powershell
npm run admin:setup
```

Команда покажет выбранный каталог данных и дважды запросит новый пароль длиной от 12 до 256 символов. Пароль не передаётся аргументом команды и не выводится открытым текстом. Готового пароля в репозитории нет.

При работающем локальном сервере открыть:

- Панель: <http://localhost:4321/admin/feedback>.
- Пример обычного урока с кнопкой внизу: <http://localhost:4321/lesson?subject=akida&course=akida-6-stolpov&slug=akida%2Fakida-6-stolpov%2F40-puti-k-mnogobozhiyu>.
- Пример интерактивного урока: <http://localhost:4321/quran/muallim-sani?lesson=nun-sukun>.

Без заданного пароля страница входа показывает инструкцию настройки. Создать администратора из общедоступной веб-страницы нельзя.

## Настройка на сервере

Для рабочего сайта использовать отдельный постоянный закрытый каталог `/srv/hutba/data/feedback`. Каталог `/srv/hutba/assets` предназначен для публичных медиа и для обращений не подходит. Путь задаётся переменной `FEEDBACK_DATA_DIR`; одинаковое значение нужно и команде настройки, и процессу сайта.

После переноса кода обновления на сервер выполнить:

```bash
sudo install -d -o hutba -g hutba -m 700 /srv/hutba/data/feedback
cd /srv/hutba/app
sudo -u hutba -H env FEEDBACK_DATA_DIR=/srv/hutba/data/feedback npm run admin:setup
```

Ввести свой пароль непосредственно в терминале. Затем добавить настройку в сервис сайта:

```bash
sudo systemctl edit hutba
```

Содержимое дополнения к сервису:

```ini
[Service]
Environment=FEEDBACK_DATA_DIR=/srv/hutba/data/feedback
```

После обычного обновления приложения применить настройку:

```bash
sudo systemctl daemon-reload
sudo systemctl restart hutba
sudo systemctl status hutba --no-pager
```

Открыть <https://hutba.org/admin/feedback>. Отправить одно пробное обращение из урока и проверить его в панели, изменение статуса и выход. Новые маршруты должны обслуживаться Node-процессом, как `/lesson`; дополнительный публичный `alias` nginx для каталога данных не нужен. Существующая схема nginx из `DEPLOY.md` уже передаёт `Host`, `X-Real-IP` и `X-Forwarded-Proto`.

Переменная должна попасть именно в окружение работающего сервиса. Одна запись в `.env` проекта или `export` в отдельной SSH-сессии не изменяет окружение уже запущенного systemd-сервиса. При проверке из терминала также указывать `FEEDBACK_DATA_DIR`, иначе команда использует локальный путь по умолчанию.

Эта инструкция не означает, что обновление уже опубликовано. В текущей задаче полная сборка и действия на рабочем сервере не выполнялись.

## Данные, резервные копии и смена пароля

По умолчанию данные лежат в `.data/feedback` относительно рабочего каталога Node. `.data/` исключён из Git и закрыт для выдачи локальным Vite-сервером. В рабочей установке рекомендован внешний путь выше, чтобы данные переживали замену каталога приложения при развёртывании.

Структура каталога:

```text
feedback/
  admin.json             хеш пароля, соль, параметры хеширования и секрет сессий
  reports/<UUID>.json     обращение, статус и история заметок
  sessions/<SHA256>.json  время окончания действующей сессии
```

Каждое обращение записывается через временный файл и атомарное переименование. Для новых каталогов и файлов на Linux задаются права `700` и `600`. Изменение записи проверяет её версию: устаревшая форма не перезапишет более новое изменение без повторной проверки администратором. Реализация рассчитана на один Node-процесс из текущей схемы systemd.

Резервировать весь закрытый каталог данных вместе с остальными резервными копиями сервера. Не переносить его в `public`, `dist/client`, `/srv/hutba/assets` или Git. Существующие обращения не удаляются при смене пароля или обычном обновлении кода.

Для смены пароля на сервере:

```bash
cd /srv/hutba/app
sudo -u hutba -H env FEEDBACK_DATA_DIR=/srv/hutba/data/feedback npm run admin:setup -- --reset
```

Локально:

```powershell
npm run admin:setup -- --reset
```

Команда заменяет хеш и секрет сессий. Все прежние входы становятся недействительными. Сессия действует до 8 часов, обычный выход отзывает её сразу. Истёкшие файлы сессий очищаются при следующем входе.

## Проверки и ограничения доступа

Пароль хранится как salted scrypt-хеш с параметрами `N=32768, r=8, p=3`, соответствующими одному из наборов в [рекомендациях OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt). Cookie сессии имеет `HttpOnly`, `SameSite=Strict`, ограничение пути `/admin` и `Secure` на рабочем HTTPS-сайте.

Административные страницы требуют действующую сессию, изменение статуса и выход дополнительно проверяют CSRF-токен и источник запроса. Публичная форма проверяет источник запроса, адрес страницы, длину текста и скрытое поле для ботов. Ограничения в одном процессе: до 5 обращений за 10 минут и до 8 попыток входа за 15 минут с одного IP; после перезапуска процесса счётчики начинаются заново. Размер тела формы ограничен 64 000 байтами. При текущем nginx доверяется только `X-Real-IP` от локального прокси.

Сообщения и заметки выводятся как текст, HTML из них не исполняется. Страницы панели и формы получают `noindex` и `Cache-Control: private, no-store`. Неавторизованный посетитель не видит ни список, ни отдельное обращение. Публичного API чтения обращений нет.

Точечная проверка серверных функций без сборки проекта:

```powershell
npm run test:feedback
```

Она проверяет хеширование и смену пароля, подпись и отзыв сессий, CSRF, закрытое хранение, адреса страниц, запись обращений и заметок, конфликт версий, ограничения тела формы, частоту запросов и заголовки. Создаёт только временные тестовые данные и удаляет их после проверки.

Дополнительно в локальном браузере проверены: обычный урок, переключение интерактивного урока, текстовый урок и отправка без JavaScript, вход и cookie, поиск, смена статусов и заметки, защита от исполнения HTML, отказ при неправильном CSRF, конфликт устаревшей формы, недоступность файлов через веб и невозможность повторно использовать cookie после выхода. Проверены мобильная и настольная компоновки. Тестовые обращения и временный пароль удалены; постоянный пароль задаёт владелец. После уточнения 20 октября подтверждение отправки оставлено отдельным экраном благодарности со ссылкой возврата к исходному уроку. Проверка включает сохранение адреса и якоря, восстановление позиции обычного и интерактивного урока, работу ссылки без JavaScript, отсутствие повторной отправки при обновлении и отмену позднего восстановления при самостоятельной прокрутке пользователя. Проверки сохранения формы при ошибке и отказа от внешнего перенаправления выполнены ранее. Поле описания проверено в обеих темах на мобильном и настольном экранах.

## Локальное горячее обновление

20 октября после изменения карточки обратной связи в работающем dev-сервере воспроизведено рассогласование: сервер интерактивного курса продолжал отдавать прежний `<section>`, клиент уже получал новый `<div>`. После перезапуска конфигурации локального сервера обе стороны используют новую разметку; повторная загрузка `/quran/muallim-sani?lesson=vakf` прошла без ошибки гидратации. Сборка не выполнялась. Если такое состояние повторяется после правок React-компонентов, перезапустить `npm run dev` и обновить страницу, чтобы получить согласованные HTML и клиентский модуль.

## Где менялся код

- `src/components/feedback/LessonFeedback.tsx` - общий блок со ссылкой. Подключён в `LessonView.astro`, `blog.tsx` и `InteractiveLessonPage.tsx`.
- `src/layouts/Base.astro` - небольшой обработчик, передающий актуальный адрес выбранного урока. Нового React-острова на обычном уроке нет.
- `src/pages/feedback/bug.astro` - форма сообщения и сохранение.
- `src/pages/admin/` и `src/components/feedback/AdminLayout.astro` - вход и административная панель.
- `src/lib/feedback/` - хранение, проверка данных, пароль, сессии и защита запросов.
- `scripts/setup-feedback-admin.mjs` - первоначальная настройка и смена пароля.
- `scripts/test-feedback.mjs` - точечные проверки.
- `.gitignore`, `astro.config.mjs`, `package.json` - закрытый каталог и команды настройки/проверки; `NavBar.tsx` - корректная подсветка меню на служебных страницах.
