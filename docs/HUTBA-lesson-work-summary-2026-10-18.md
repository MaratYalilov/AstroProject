# Итог работы над страницей урока

Дата: 18 октября 2026 года. Отчёт охватывает аудит сайта, правки доступности, оптимизации страницы урока и вынос статьи из React-острова.

## 1. Кратко

Страница урока прошла путь от PSI 59 до 89-90 на мобильном. Главные изменения:

- статья и медиа отдаются серверным HTML, а не через большой React-остров;
- программа курса стала статическим списком из 104 ссылок без гидрации;
- QCF-шрифты грузятся по видимости, Amiri переведён в WOFF2;
- постер видео получил preload с высоким приоритетом;
- дублирование мобильного и десктопного лейаута убрано.

TBT на мобильном упал с 450-500 мс до 10-40 мс. На десктопе до статической программы был TBT 710 мс: длинная задача 1034 мс в `client.js` оказалась гидрацией программы курса. После перевода программы на статический список задача сместилась в `Base.astro`: 842 мс, TBT 840 мс. Следующий шаг - разобрать инициализацию Base.

## 2. Исходная точка

- Astro 7.3.5, React 19, SSR для `/lesson`, статические страницы для остального сайта.
- 8 предметов, 25 курсов, 1328 уроков, 369 статей словаря.
- QCF: 604 страницы мусхафа, 6236 аятов, отдельные WOFF2 на страницу.
- Страница урока собиралась большим островом `LessonPage`: в props передавался весь HTML статьи, туда же входили медиа, тулбар, программа курса и прогресс.
- Мобильная и десктопная ветки лейаута дублировались: две `<video>`, два набора терминов, лишние QCF-блоки.

Первые замеры PSI: 59/100, FCP 1,7 с, LCP 4,3 с, TBT 1470 мс, SI 2,6 с. Передача 1780 КБ, шрифты 1359 КБ семью файлами, DOM около 2967.

## 3. Аудит и правки страниц

- На главной и страницах уроков приведён в порядок `h1`: один видимый или один sr-only заголовок.
- Удалён неиспользуемый `lessonsCount`.
- Консолидирован `TheoryReveal`.
- Для неизвестного `/lesson?slug=...` добавлен 404 с видимым заголовком и ссылкой на курс; канонический адрес ведёт на курс.
- Голый `/lesson` без `subject` и `course` больше не отдаёт пустую 500: теперь 302 на главную.
- Словарь: sr-only `h1` при отсутствии активной статьи, скелетон загрузки, видимые в тёмной теме полосы.
- Тёмная тема: исправлен скелетон теории.
- Формулировка «просмотрено (условно)» заменена на «пройдено».
- В учебнике добавлено мобильное оглавление: кнопка-гамбургер, выдвижная панель, закрытие по Escape и клику по фону, блокировка прокрутки страницы.

## 4. Производительность: первый этап

- QCF-шрифты загружаются через `IntersectionObserver` с запасом в один экран; до готовности шрифта виден читаемый Unicode, глифы скрыты.
- Amiri переведён из TTF в WOFF2: 411/395/409/391 КБ → 141/132/144/135 КБ, экономия 65-66%, вид не изменился.
- `GlossaryOverlay` переведён с `client:load` на `client:idle`.
- Постер видео получил `<link rel="preload" as="image" fetchpriority="high">`.
- Итог этапа: передача 1780 → 562 КБ, шрифты 1359 → 141 КБ, DOM 2967.

Локальный TBT после этих правок давал 3694-3868 мс, но на этой машине он недостоверен: PSI показывал 380-510 мс. Для TBT основным источником остаётся PSI.

## 5. Дедупликация лейаута

`LessonPage` сведён к одной адаптивной ветке:

- одна `<video>` вместо двух;
- один `h1`;
- 24 ссылки-термина вместо 48;
- 12 QCF-блоков вместо 18;
- DOM 2967 → 2004 в dev, 1547 на проде;
- HTML 585 → 370 КБ.

PSI после публикации: 79, затем 87/100 при FCP 1,7 с, LCP 2,2 с, TBT 450 мс, CLS 0,002, SI 1,7 с.

## 6. Вынос статьи из React-острова

### Что сделано

- `src/lib/lessonContent.ts` делит HTML урока на текстовые куски и карточки словаря.
- `LessonArticle.astro` отдаёт статью серверным HTML, карточки подключаются как `client:visible`.
- `LessonView.astro` содержит общую оболочку: заголовок, видео/аудио, тулбар, статью, программу и скрипты.
- `LessonCompleteButton` остался маленьким островом, `LessonPrevNext` стал серверным компонентом.
- `src/pages/lesson.astro` и `src/pages/[subject]/[course].astro` используют общий `LessonView`.
- `LessonPage.tsx` удалён.
- Медиа стало нативным: `<video>` и `<audio>` без React, переключение видео/аудио на маленьком скрипте.
- Добавлено правило `[hidden] { display: none !important; }`, иначе Tailwind-класс `flex` перебивал скрытие аудио-обёртки.

### Результат

- HTML статьи больше не сериализуется в props острова.
- Props островов: около 370 КБ статьи → 18,1 КБ.
- В HTML урока пять островов: навигация, словарь, кнопка «Наверх» и две кнопки завершения.
- Статья, медиа и программа проверены на уроке 40; отдельно проверены урок без медиа, словарные карточки, 404, учебник и интерактивный курс.

### PSI после выкладки статьи

- Мобильный (до статической программы): 89-90/100, FCP 2,5 с, LCP 3,2 с, TBT 10-40 мс, CLS 0-0,002, SI 3,2-3,3 с.
- Десктопный (до статической программы): 74/100, FCP 0,3 с, LCP 0,7 с, TBT 710 мс, CLS 0,001, SI 0,7 с.

Десктопный TBT 710 мс был подтверждён локальным Lighthouse: 1040 мс, длинная задача 1034 мс в `/_astro/client.Ce4J-xac.js`. Это гидрация островов, а не сторонний скрипт.

После перевода программы на статический список локальный desktop Lighthouse: 66/100, FCP 0,5 с, LCP 0,6 с, TBT 840 мс, SI 3,0 с. Длинная задача 842 мс теперь в `/_astro/Base.astro_astro_type_script_index_0_lang.CQbWle3x.js`; гидрация `CourseProgram` ушла.

### Почему mobile и desktop расходятся

TBT считает задачи между FCP и TTI. На мобильном сеть и CPU медленнее, `client:idle`-острова могут гидрироваться после TTI и не попадать в TBT. На десктопе тот же код успевает гидрироваться раньше и попадает в окно измерения. Поэтому TBT нельзя сравнивать между mobile и desktop напрямую. После статической программы остаток на десктопе - уже не гидрация программы, а инициализация `Base`.

## 7. Статическая программа курса

Уже на проде, коммит `7b9e423`:

- `CourseProgram.tsx` заменён на `CourseProgram.astro`.
- 104 урока отдаются обычным HTML, без React-гидрации.
- Поиск, прогресс, badge завершённого, прокрутка к текущему и подсветка совпадений работают на маленьком vanilla-скрипте.
- Props островов: 18,1 → 0,4 КБ.
- Остров `CourseProgram` исчез.

Проверено на уроке 40:

- 104 пункта, текущий урок подсвечен и прокручен в видимую область;
- «Отметить завершённым»: прогресс 0% → 1%, у пункта появляется завершённое состояние;
- поиск «единобожие»: 4 видимых пункта, 3 подсвеченных совпадения и текущий урок, добавленный принудительно;
- очистка возвращает 104 пункта и восстанавливает заголовки посимвольно;
- подсветка совпадений использует прежние классы `bg-yellow-200/70` и `dark:bg-yellow-500/30`.

После выкладки ожидание не подтвердилось: desktop TBT 840 мс, длинная задача 842 мс в `Base.astro`. `CourseProgram` больше не гидрируется; остаток - инициализация Base (QCF, wasl, mermaid).

## 9. Что откатано и почему

- **Удаление 604 правил QCF из `qcf-v2.css`.** Файл сгенерирован, семейство назначается через `.qcf-page-N`, README прямо описывает этот слой. После удаления глифы не включались; файл восстановлен.
- **Удаление framer-motion и отложенная инициализация QCF.** После публикации PSI дал 76/100 при 87 до правок; изменения откатаны. Урок: один прогон PSI не доказывает регрессию, но и выигрыш не подтвердился.
- **Длинная задача в скрипте `Base.astro`.** После статической программы на десктопе подтверждена задача 842 мс; QCF, wasl и mermaid-инициализация остались как были, точная причина внутри Base не изолирована.
- **`NO_LCP` в одном отчёте PSI.** Оказался сбоем прогона; страница стабильно отдаёт 200, локально LCP считается.

## 10. Где сейчас граница прод/локально

На проде и в коммите `7b9e423`: `LessonView`, статическая программа, удалённый `LessonPage`, страница курса на общей оболочке. Mobile 89-90 и desktop 74 были сняты до статической программы; desktop 840 получен локально после её выкладки.

В рабочем дереве код не менялся; изменён план `HUTBA-promotion-plan.md` и добавлен этот отчёт. Коммит и пуш выполняет владелец.
