# Проба встроенных стилей на странице «Азан»

19 октября 2026 года. Применяется к прямой загрузке `/glossary/azan` и `/glossary/azab-al-kabr`, включая адреса с завершающим `/`. Остальные статьи и страницы используют прежний CSS. Вторая статья добавлена после отдельного сравнения, описанного в [замере «Азаб аль-кабр»](HUTBA-glossary-azab-performance-2026-10-19.md).

В HTML встраиваются правила из действующего Tailwind CSS, подходящие к классам исходной страницы. Это консервативный набор для всей исходной разметки, а не только правил, отмеченных Coverage одного экрана. Сохраняются порядок правил, media/supports, обе темы, псевдоклассы, правила без классов и объявления шрифтов. Оформление вручную не переписано.

Внешний файл со всеми остальными правилами подключён через `media="print"`, затем обработчик загрузки включает `media="all"`. В нём нет повторных `@font-face`: они уже встроены в HTML. Адрес содержит хеш CSS, поэтому новая версия стилей получает новый адрес. Без JavaScript используется `noscript` с обычным подключением оставшихся стилей. При неоднозначном наборе внешних CSS или отсутствии полезного сокращения сохраняется первоначальное подключение.

Файлы реализации:

- `src/middleware.ts` - ограничивает преобразование двумя проверенными адресами, работает при предварительном рендеринге и в dev.
- `src/lib/criticalCss.ts` - извлекает набор и заменяет подключение CSS; учитывает HTML-экранирование классов вроде `[&amp;_svg]:size-4`.
- `src/lib/azanCss.ts` - берёт CSS через Vite `?inline`, готовит отложенный CSS без повторных объявлений шрифтов и хеш адреса.
- `src/pages/styles/azan/[hash].css.ts` - статический CSS-адрес для отложенных правил.
- `scripts/test-critical-css.mjs` - точечная проверка отбора правил, сохранения одного владельца шрифта, noscript и безопасного отказа от преобразования.

В `package.json` и lock-файле существующий `postcss-selector-parser` объявлен прямой зависимостью разработки. Новые версии пакетов не устанавливались. Обработчик и текст Корана, файлы шрифтов, их начальная цепочка и QCF-загрузчик не менялись.

## Локальный результат

Сравнивалась неизменяемая копия опубликованного HTML и ресурсов из отчёта `ogx9vy2iro`, обслуживаемая обычным локальным HTTP-сервером с gzip. Это не сборка Astro. Сервер разработки уже встраивает весь CSS, поэтому сравнение только его FCP не показало бы устранение запроса, который есть на домене.

Шесть последовательных холодных загрузок, чередование исходного и пробного вариантов, по три запуска. Edge/Chromium, 400 x 861, CPU x4, сеть 180000 байт/с, задержка запросов 562,5 мс, кеш отключён. Для каждого запуска новый браузерный контекст.

| Метрика, медиана | Исходный | Встроенный набор |
| --- | ---: | ---: |
| FCP | 1,444 с | 0,704 с |
| LCP | 6,104 с | 5,544 с |
| CLS | 0 | 0 |
| Передача | 658197 байт | 664437 байт |

FCP улучшился на 0,740 с, LCP на 0,560 с. Передача выросла на 6240 байт: часть правил повторяется во встроенном наборе и отложенном файле. HTML gzip 30255 -> 36642 байта. Встроенный CSS опубликованного снимка 22638 байт до сжатия вместо общего CSS 117173 байта. Отложенный файл в этих запусках готов примерно к 1,48 с, первый показ уже к 0,70 с.

Это сравнение двух вариантов одной локальной копии в одном браузере. Эти цифры нельзя приравнивать к PageSpeed или пользовательской записи Chrome с LCP 2,074 с: здесь итоговый LCP обновляется после готовности начертания. Во всех шести запусках элемент LCP одинаковый - первый арабский абзац. Публикация и новый PSI ещё не выполнялись.

## Проверки

- На ширинах 400, 768 и 1350 в обеих темах: расчётные стили/геометрия совпали с исходными, шесть снимков первого экрана совпали попиксельно даже при задержанном отложенном CSS. После его подключения геометрия не изменилась.
- В обоих вариантах каждый шрифт запрашивается один раз. При подготовке пробы обнаружены и устранены повтор Amiri и отличие размеров иконок.
- Переключение темы, мобильное меню и чтение без JavaScript проверены.
- На настоящем dev-сервере Astro `/glossary/azan` содержит встроенный набор, `/glossary/avrat` сохраняет прежний вариант. CSS-адрес с хешем возвращает 200, правильный Content-Type, ноль `@font-face`, хеш содержимого совпадает с адресом.
- Переход Азан -> список -> Аврат -> список -> Азан работает, повторных загрузок QCF и ошибок JavaScript нет.
- Точечный тест и проверка типов новых файлов прошли. Сборка не запускалась.

Проверять визуально: `http://localhost:4321/glossary/azan` и `http://localhost:4321/glossary/azab-al-kabr`. После публикации владельцем нужны те же адреса на домене: проверить отсутствие блокирующего общего CSS, один запрос каждого шрифта, FCP/LCP по нескольким запускам. Остальные страницы в пробу не включены.
