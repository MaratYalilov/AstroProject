# Предпросмотр ссылок

## Нужно ли создавать public/covers?

Для автоматических карточек создавать папку `public/covers` не нужно.
Карточки уже подключены и создаются по запросу. Эта папка нужна только
если вы хотите использовать собственные готовые JPG или PNG.

`covers` — удобное название папки, а не специальное требование Astro.
Можно хранить обложки в другой папке внутри `public` или использовать
изображение по внешнему HTTPS URL.

## Как создаётся автоматическая карточка

1. Страница передаёт в `Base.astro` название и, при необходимости,
   название курса и код предмета.
2. `Base.astro` добавляет в HTML тег `og:image` с полным URL картинки.
   Например, для предмета «Акида» URL содержит параметры `title=Акида`,
   `subtitle=Предмет`, `subject=akida` и версию оформления `v=2`.
3. Когда сервис предпросмотра запрашивает этот URL, серверный маршрут
   `/social-preview.png` рисует PNG 1200×630 и отдаёт его как изображение.
4. Генератор берёт оформление из `src/utils/socialCard.ts`, иконку из
   `public/subject-icons` и встроенный шрифт Noto Sans. Длинное название
   переносится на несколько строк; при необходимости шрифт уменьшается.

Логотип берётся из `src/assets/social/hutba-logo.svg` и вписывается в область
до 420×100 пикселей с сохранением пропорций. В файле обрезаны пустые поля
экспорта, фон прозрачный. При замене логотипа обновите также версию `v`.

Отдельный файл для каждой страницы на диске не создаётся. Сервер хранит
последние 64 карточки в памяти, чтобы повторные запросы не требовали
перерисовки. После перезапуска сервера они создаются заново по запросу.

На обычных страницах используется их название. У предметов — название
предмета и его иконка; у курсов — название курса и иконка предмета;
у уроков — название выбранного урока, название курса и иконка предмета.
Для урока с видео сначала используется существующая JPG-миниатюра видео,
если для урока не задана собственная обложка `ogImage`.

На обычной странице достаточно:

```astro
<Base title="О проекте">
  ...
</Base>
```

В `Base` также можно передать:

| Параметр | Что меняет |
| --- | --- |
| `ogTitle` | Заголовок предпросмотра и основной текст карточки; по умолчанию равен `title` |
| `ogSubtitle` | Небольшую строку над основным текстом картинки |
| `ogSubject` | Иконку предмета: например, `akida`, `quran` или `arabic` |
| `ogImage` | Заменяет автоматическую карточку готовой картинкой |
| `ogImageAlt` | Текстовое описание картинки в метаданных |

## Как поставить собственную обложку

Например, чтобы у предмета «Акида» была ваша картинка:

1. Создайте папку `public/covers`.
2. Положите в неё файл `akida.jpg`.
3. В `src/content/subjects/akida.yml` добавьте строку:

```yaml
ogImage: "/covers/akida.jpg"
```

Файл `public/covers/akida.jpg` будет доступен на сайте как
`https://hutba.org/covers/akida.jpg`. В значении `ogImage` префикс `public`
не указывается. Указанный файл нужно создать: генератор не создаёт его
по имени из `ogImage`.

Такое же поле можно добавить в YAML курса, frontmatter Markdown урока
или термина. Frontmatter — блок между `---` в начале Markdown-файла:

```markdown
---
title: "Название урока"
ogImage: "/covers/my-lesson.jpg"
---

Текст урока...
```

У интерактивного урока поле `ogImage` задаётся в его JSON.

Для обычной `.astro`-страницы готовая обложка передаётся в `Base`:

```astro
<Base title="О проекте" ogImage="/covers/about.jpg" ogImageAlt="Обложка проекта HUTBA">
  ...
</Base>
```

Можно также использовать внешний файл:

```yaml
ogImage: "https://example.com/my-cover.jpg"
```

## Как выбирается картинка

| Страница | Приоритет |
| --- | --- |
| Предмет | Его `ogImage` → автоматическая карточка |
| Курс | `ogImage` курса → `ogImage` предмета → автоматическая карточка |
| Урок с видео | `ogImage` урока → существующая миниатюра видео → `ogImage` курса → `ogImage` предмета → автоматическая карточка |
| Урок без видео | `ogImage` урока → `ogImage` курса → `ogImage` предмета → автоматическая карточка |
| Термин словаря | Его `ogImage` → автоматическая карточка |
| Обычная страница | `ogImage`, переданный в `Base` → автоматическая карточка |

Готовая обложка предмета используется его курсами и уроками, у которых
нет собственной обложки или миниатюры видео. Если ни обложки, ни миниатюры
нет, создаётся автоматическая карточка с названием.

У Markdown-уроков в `/lesson` путь к миниатюре определяется по адресу
выбранного видео (`videoRel` или `video`). Например:

```text
Видео:     /media/akida/akida-6-stolpov/video/01-vstuplenie-shest-stepeney-imana.mp4
Миниатюра: /media/akida/akida-6-stolpov/thumbs/01-vstuplenie-shest-stepeney-imana.jpg
```

При разработке миниатюра ищется в `public/media`, после сборки также в
`dist/client/media`. На Linux сначала проверяется медиатека рабочего сайта
`/srv/hutba/assets/media`. Например, URL `/media/akida/akida-at-tahawiya/thumbs/02-biografiia-avtora-i-kommentatora.jpg`
соответствует файлу `/srv/hutba/assets/media/akida/akida-at-tahawiya/thumbs/02-biografiia-avtora-i-kommentatora.jpg`.

Другой путь можно задать переменной окружения `HUTBA_MEDIA_ROOT` при запуске
Node. Она указывает непосредственно на каталог `media`, а не его родителя.
Новые миниатюры определяются при запросе страницы без обновления списка
или пересборки приложения. Если JPG отсутствует, используется следующий
вариант из таблицы. Внешние видео не получают предполагаемую миниатюру:
для них можно явно указать `ogImage`.

Проверка выбора картинки: `npm run test:lesson-preview`.

## Публикация и изменение оформления

Названия и иконки попадают в картинку на сервере, без выполнения JavaScript
в браузере посетителя. При развёртывании нужны сервер Node и каталог
`dist/client`, включая `_astro` (встроенный шрифт Noto Sans под лицензией OFL).
Сам генератор, страницы и готовые обложки должны быть опубликованы,
чтобы сервис предпросмотра мог запросить их с `hutba.org`.

Для изменения оформления обновите `src/utils/socialCard.ts` и версию `v`
в `src/utils/socialImage.ts`, чтобы URL картинки изменился. Изменение
названия страницы также меняет URL автоматически. При замене готовой
обложки можно дать ей новое имя и обновить `ogImage`.
